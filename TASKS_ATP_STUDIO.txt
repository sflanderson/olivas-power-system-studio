Sprint v0.91.7 (concluída) — HOTFIX DEFINITIVO SIGNALRELAY:

Bug crítico do v0.91.6 PERSISTIU mesmo após Qt.QueuedConnection
explícito. Code review profundo identificou que PySide6 NÃO
respeita Qt.QueuedConnection quando signal.emit() vem de Python
threading.Thread (não-QThread) — fall-through pra
DirectConnection → slot roda no thread errado → crash visível
no app + erros Qt no console.

Solução canônica Qt C++: QMetaObject.invokeMethod, que SEMPRE
posta event de baixo nível na queue do thread do receiver,
independente do caller.

Implementação:

1. SIGNALRELAY (novo) — app/gui/signal_relay.py:
   * QObject vive no main thread.
   * post_*() (chamáveis de qualquer thread) usam
     QMetaObject.invokeMethod canonical.
   * Slots @Slot rodam no main → emitem signals locais.
   * Receivers rodam em DirectConnection (todos main).

2. WORKER ACEITA RELAY — app/gui/async_runner.py:
   * AtpRunWorker.__init__ aceita relay opcional.
   * run() rota emits via relay.post_*() quando presente.
   * make_run_thread aceita relay; conecta thread.quit a
     relay.run_finished/cancelled.

3. MAINWINDOW USA RELAY — app/gui/main_window.py:
   * _on_run_atp cria SignalRelay no main thread.
   * Todas connections via relay → widgets.

4. CHAT_WIDGET AUDIT — Claude API mesma classe de bug
   (_ClaudeWorker é threading.Thread). Aplicado
   Qt.QueuedConnection EXPLÍCITO nas 3 conexões.

5. WORKAROUND Q_ARG(object): PySide6 não aceita object como
   meta-type. post_finished(result) armazena em
   self._pending_result (Lock) e _emit_finished() lê +
   emite — evita Q_ARG(object).

Sprint v0.84.1 (concluída) — QT SIGNAL BOOL POISONING FIX:

Hotfix de regressão runtime reportado pelo usuário:

  Traceback ...
    File "app/gui/analysis_dialogs.py", line 635
      for c in project.components:
  AttributeError: 'bool' object has no attribute 'components'

Causa raiz: ``QAction.triggered`` é signal Qt com bool
``checked`` como primeiro arg posicional. Slots dos
handlers ``_on_analyze_*(self, project=None, bus_id="")``,
quando conectados via ``addAction(text, slot)`` ou
``triggered.connect(slot)``, recebiam o bool em ``project``,
contaminando o downstream.

Fix:
``def _on_analyze_*(self, *_qt_args, project=None, bus_id="")``
— ``*_qt_args`` absorve o bool; ``project``/``bus_id``
passam a ser keyword-only. Aplicado nos 5 handlers
(bus_pipeline, sc, pf, motor, arc_flash). Callers internos
via kwargs (``_dispatch_analysis``, RunAnalysisDialog,
testes) inalterados.

Tests: 7 novos (test_pp_v0_84_1_qt_signal_bool_fix.py).
Suite acumulada: 3180 testes passando.
