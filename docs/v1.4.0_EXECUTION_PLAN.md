# v1.4.0 Execution Plan — Custom Label Designer (Arc-Flash)

**Sprint**: v1.4.0 (último P0 do roadmap original AUDIT v1.1.0)
**Janela**: ~2 semanas
**Pré-requisito**: v1.3.2 entregue (480/480 verde, GUI integration 100%)
**Lição aplicada v1.3.1**: **GUI gate desde início**, não como afterthought.

---

## Objetivo

Atingir paridade com PTW Power*Tools "Custom Label Designer" — gerador
de labels arc-flash imprimíveis NFPA 70E / NESC. Este é o **deliverable
visual mais importante** para compliance comercial.

PTW oferece:
- 30 text fields user-customizable (Bus name, kV, Ik'', PPE category, etc.)
- 8 picture fields (logos, warning icons)
- Multilingual via Keyword Table
- Clothing Category dynamic colors (Dangerous=vermelho, Warning=laranja)
- Page size + orientation + X/Y/W/H position

Olivas v1.3.2 tem `arc_flash.py::ArcFlashReport` com **todos os dados**
necessários para popular o label. Falta apenas o gerador + GUI.

---

## Princípios de execução (lição aprendida v1.3.1)

1. **GUI gate desde início**: cada sub-sprint inclui teste GUI + backend
2. **Não modificar `arc_flash.py`** (compatibilidade — tem testes existentes)
3. **TDD por sub-sprint** com aceite verde
4. **Anti-alucinação**: cada field cita seção da NFPA 70E ou NBR 17227
5. **Sem deps externas** (HTML standalone, sem ReportLab/Pillow)
6. **Sub-sprints reverterveis**: cada commit isolado
7. **Documentação inline** + log incremental

## Faseamento

### Sub-sprint A — LabelTemplate + ArcFlashLabel data model + render HTML
**Estimativa**: ~250 LOC + 12 testes

**Entregáveis**:
- `app/postprocessor/arc_flash_label.py`:
  - `ArcFlashLabel` frozen dataclass com 30 fields (texto + algumas booleanas)
  - `from_arc_flash_report(report, **overrides)` classmethod (auto-fill)
  - `LabelStyle` enum: NFPA70E_2024, NESC_2023_TYPE_4_5, MINIMAL_BR
  - `render_html_label(label, style)` produz HTML print-ready (CSS @media print)

**30 fields PTW-equivalent** (cita norma cada um):
1. Bus Name
2. Bus kV (rated voltage)
3. Bolted Fault Current (Ibf, kA)
4. Arcing Fault Current (Iarc, kA)
5. Arc Duration (ms)
6. Equipment Type (Switchgear/Panel/MCC/Cable/Open Air)
7. Gap (mm)
8. Working Distance (mm)
9. Electrode Configuration (VCB/VCBB/HCB/VOA/HOA)
10. Incident Energy (cal/cm²)
11. Arc Flash Boundary (mm)
12. PPE Category (0/1/2/3/4 ou DANGER)
13. PPE Description (NFPA 70E Tabela 130.7(C)(15)(c))
14. Limited Approach (mm)
15. Restricted Approach (mm)
16. Glove Class (00/0/1/2/3/4)
17. Glove Class Voltage Rating (V)
18. Shock Hazard Voltage (V)
19. Flash Hazard Range (cal/cm²)
20. Head & Eye & Hearing Protection (text)
21. Hand & Arm Protection (text)
22. Foot Protection (text)
23. Notes / Codes (*N1, *N2, ...)
24. Date Computed
25. Computed By (engenheiro)
26. Project Title 1
27. Project Title 2
28. Equipment Owner
29. Label Number / Serial
30. Audit SHA256 (rastreabilidade ISO 9001 / NR-10)

**Testes A**:
- Construção from_arc_flash_report
- 3 estilos renderizam HTML válido
- DANGER → vermelho; CAT 4 → laranja; CAT ≤ 1 → verde (clothing dynamic color)
- HTML XSS-safe
- Audit SHA256 presente quando fornecido

## Riscos antecipados

| Risco | Mitigação |
|---|---|
| 30 fields é muito (overengineering) | Começar com 30, mas marcar opcionais (default vazio) |
| HTML print não renderiza igual em todos browsers | CSS standard + @media print + testar Chrome/Firefox/Edge |
| Picture fields (8) requer Pillow | v1.4.0 entrega só text fields; pictures ficam v1.4.1+ |
| Multilingual Keyword Table complexo | v1.4.0 entrega só PT-BR + EN; multilingual via plugin v1.5+ |
| QTableWidget edição é trabalhoso | Usar QLineEdit em cada cell (pattern Qt nativo) |
| Live preview lento se re-render por keystroke | Debounce 300ms via QTimer |
