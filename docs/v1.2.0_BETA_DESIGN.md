## Problema

Em v1.1.0, cada `TCCCurve` (legacy) modela **uma única função** de proteção (51 IDMT). Para um relé real como SEL-751 ou ABB REF615, que tem **múltiplas funções simultâneas** (50/51/49/87), o usuário precisava criar 3-4 instâncias separadas. Isso:

1. **Confunde a UI** (3 entradas na lista para "1 relé real")
2. **Não modela o comportamento real** (a função que dispara primeiro é a que conta — ``min(t_50, t_51, t_49)`` não é trivial num for-loop ad-hoc)
3. **Dificulta coordenação** (preciso comparar relé-vs-relé, não função-a-função)

PTW Power*Tools resolve isto com "Multiple Functions per Protection Component" no CAPTOR — um único device tem N segments, e a curva visível é o **composite envelope**.

---

## Solução: TCCDevice + MultiFunctionRelay

### β.1 — `TCCDevice` (base genérica)

```python
@dataclass(frozen=True)
class TCCDevice:
    """Container de N TCCSegments formando um dispositivo de proteção."""
    device_id: str
    manufacturer: str = "Generic"
    model: str = "Generic"
    segments: tuple = ()           # tuple[TCCSegment, ...]

    def composite_time_at_current(self, I: float) -> float:
        """min(t_segment) sobre enabled."""
        return composite_time_at_current(self.segments, I)

    def composite_points(self, ...):
        """Pontos do envelope composto."""

    def with_segment_enabled(self, idx, enabled) -> "TCCDevice":
        """Retorna nova instância com 1 segment toggled."""

    def with_segment_added(self, segment) -> "TCCDevice":
        """Retorna nova instância com 1 segment a mais."""
```

**Decisões**:
- `frozen=True` para consistência com Olivas (todos os segments são frozen)
- `tuple` (não list) para imutabilidade real — `dataclass(frozen=True)` só congela atribuição da referência, não o conteúdo de uma list
- Métodos `with_*` retornam nova instância (pattern functional)
- `composite_time_at_current` reusa função existente em `tcc_segments.py`

### β.2 — `MultiFunctionRelay` (subclasse com helpers)

```python
@dataclass(frozen=True)
class MultiFunctionRelay(TCCDevice):
    """Subclasse para relés com helpers convenientes."""

    # Construtores convenientes (classmethods):
    @classmethod
    def relay_51_only(cls, device_id, curve_type, pickup_A, tms,
                      manufacturer="Generic", model="Generic"):
        """Relé com apenas IDMT 51."""

    @classmethod
    def relay_51_and_50(cls, ..., pickup_50_A, delay_50_s=0.04):
        """Relé com 51 + 50 (instantâneo)."""

    @classmethod
    def relay_51_50_49(cls, ..., motor_thermal_pickup_A,
                       motor_thermal_delay_s):
        """Relé motor: 51 + 50 + 49 thermal (DefiniteTime)."""

    @classmethod
    def relay_51_50_87(cls, ..., diff_pickup_A, diff_delay_s):
        """Relé transformador: 51 + 50 + 87 diferencial."""
```

**Decisões**:
- Subclasse para preservar tipagem (verificações `isinstance(d, MultiFunctionRelay)` na GUI futura)
- 4 construtores cobrem os 4 padrões mais comuns (90% dos casos reais)
- Cada classmethod compõe os segments fundacionais já testados (α.1) — sem código novo de fórmulas

### β.3 — `check_device_coordination(upstream, downstream, fault_A)`

```python
@dataclass(frozen=True)
class DeviceCoordinationCheck:
    """Resultado de coord device-vs-device (multi-segment-aware)."""
    upstream_id: str
    downstream_id: str
    fault_current_A: float

    upstream_composite_time_s: float
    downstream_composite_time_s: float
    actual_delta_t_s: float
    required_delta_t_s: float
    passes: bool

    # Detalhes por par (segments individuais que ditaram a decisão)
    triggered_upstream_segment: str   # qual segment do up disparou
    triggered_downstream_segment: str # qual segment do dn disparou


def check_device_coordination(
    upstream: TCCDevice,
    downstream: TCCDevice,
    fault_current_A: float,
    relay_type: str = "digital",
) -> DeviceCoordinationCheck:
    """Verifica Δt usando composite envelope de ambos."""
```

**Decisões**:
- `triggered_*_segment` ajuda debug ("o INST do upstream venceu o LT do downstream → Δt insuficiente")
- Reusa `COORDINATION_MARGIN_S` de `tcc_curves.py` (legacy)
- Não recomputa cada par segment×segment — só usa composite envelope (que JÁ é o que dispara primeiro)

## Riscos antecipados

| Risco | Mitigação |
|---|---|
| Confusão TCCDevice vs TCCCurve | Glossário explícito + import claro; documentar diferença |
| Tuple vs list em frozen dataclass | Explícito no docstring + assertion em `__post_init__` |
| Subclasse de frozen dataclass não funciona "out of the box" no Python | Testar em β.2; se quebrar, usar composição em vez de herança |
| Coordenação device-device perde info de qual segment disparou | Nova classe `DeviceCoordinationCheck` carrega `triggered_*_segment` |
| Helpers de relay viram bagunça (50+51+49+87+...) | Limitar a 4 padrões em β.2; outros via API base |
