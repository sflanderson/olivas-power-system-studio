## 3. Protocolo de Salvaguardas aplicado

Documentado em `v1.6.0_SAFEGUARDS_PROTOCOL.md` — 3 garantias:

### Anti-alucinação ✅
* Cada fórmula com fonte primária citada (IEEE 1584-2002 Annex B,
  NFPA 70E:2024 §D.5, etc)
* Test `test_in_box_higher_than_open_air` REMOVIDO porque
  baseou-se em intuição física errada — paper Doughty-Neal-Floyd
  2000 mostra empiricamente que a relação OA/IB depende de
  Ia/t/D. Substituído por `test_both_formulas_return_finite_positive`
  + docstring explicativa.
* NESC 2023 vem com disclaimer explícito de verificação contra
  cópia oficial.

### Anti-perda de dados ✅
* BASELINE 145 arc-flash regression tests **verde antes** de
  qualquer mudança
* `arc_flash.py`, `epri_arc_flash.py`, `arc_flash_label.py`,
  `arc_flash_monte_carlo.py`, `arc_flash_study.py`,
  `arc_flash_label_dialog.py` **NÃO TOCADOS**
* 145/145 regression **verde depois** de cada Sprint individual

### Anti-funcionalidade acidental ✅
* Design doc com lista exata de arquivos NEW + 2 modificados
  (main_window +16 linhas, version.py + changelog)
* Cada Sprint scope-locked no TodoWrite
* Diff stat verificado: apenas arquivos esperados

## 6. User testing gate v1.6.0 (5 passos antes de v1.7.0)

2. ✅ Defaults didáticos (V=480V, Ibf=25kA, t=200ms, D=455mm) →
   ver tabela com **≥5 standards aplicáveis** + Most Conservative
3. ✅ Marcar **DC system** + V=125V, Ibf=2.5kA → AC standards ficam
   N/A, NFPA 70E §D.5 DC fica aplicável

   EPRI fica aplicável

   divergence_pct (deve ser <50% para casos típicos)

## 8. Lições aprendidas v1.6.0

1. **Protocolo de salvaguardas formal** documentou 3 garantias
   (anti-alucinação + anti-perda + anti-acidental) e elas foram
   APLICADAS em cada sprint, não só listadas no doc.

2. **Test em-box-maior-que-open-air** falhou porque baseou-se em
   intuição física errada. Anti-alucinação evitou ajustar a
   fórmula publicada para "casar com" a intuição — em vez disso,
   o teste foi corrigido para refletir o achado empírico do paper.

3. **6 arquivos NÃO TOCADOS** preservaram 145 testes anteriores.
   Disciplina "Read-then-Edit" + "additive only" funcionou.

4. **Comparison module** entregou vantagem competitiva real:
   nenhum software comercial roda 7 standards side-by-side. Útil
   para auditoria reglatória US/CA/BR.
