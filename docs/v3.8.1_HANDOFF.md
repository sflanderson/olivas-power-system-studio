## 4. Sprint C.4 — Q-limit switching (IEEE 399 §5.3.4)

### Mudanças em `PfBus`
NEW campos:
```python
Q_min_pu: float = -1e9          # default sem limite
Q_max_pu: float = 1e9
original_type: BusType | None = None  # auditável após switch
```

### Mudanças em `PowerFlowSystem.add_pv`
Aceita `Q_min_pu`/`Q_max_pu` kwargs com defaults effectively-infinite
(backward-compat).

### NEW `solve_with_q_limits(...)` method
Algoritmo (IEEE 399 §5.3.4):
1. Resolve via Newton-Raphson
2. Para cada PV bus: se `Q_solved > Q_max` ou `Q_solved < Q_min`:
   - `bus.type = PQ`
   - `bus.Q_pu_set = Q_max` ou `Q_min` (limit violado)
   - Append violation message
3. Re-resolve. Loop até `max_switching_iterations=5` ou nenhum switching.
4. Anexa `q_limit_violations: list[str]` à `PowerFlowSolution` via
   `object.__setattr__` (frozen-aware).

## 9. Anti-alucinação — limitações declaradas

1. **C.3 fixture é subset** — apenas 5 buses do IEEE 14-bus; os
   golden values são approximados (loose tol). Full 14-bus + IEEE 30-bus
   fixtures deferred.

2. **C.4 switching é greedy** — pega o primeiro PV violando e switching;
   não otimiza ordem. Casos com múltiplos violations simultâneos podem
   precisar mais switching iters.

3. **Q-limits não cobrem PQ→PV "back-transition"** — uma vez que PV
   vira PQ, fica PQ. IEEE 399 §5.3.4 também menciona reverse switch
   se Q-limit volta a ser respeitado (deferred).

4. **Slack switching não implementado** — apenas PV→PQ. Slack permanece
   slack mesmo com violation. Multi-slack switching deferred.

5. **`q_limit_violations` é list[str] descritivo** — não estruturado.
   Para análise programmatic, parser seria necessário (deferred).
