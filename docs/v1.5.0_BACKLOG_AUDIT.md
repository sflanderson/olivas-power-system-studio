## 2. Research: padrões de plugin marketplace

### 2.1 VS Code Extensions (modelo de referência)

* **Manifest** (`package.json`): name, version, publisher, description,
  engines, contributes, activationEvents, permissions
* **Marketplace UI**: 3 tabs (Installed / Recommended / Settings)
* **Lifecycle**: discovered → installed → enabled → disabled →
  uninstalled (persisted em `extensions.json`)
* **Permissions**: extensions declaram contributions (commands, themes,
  views) — VS Code não pede confirmação por contribution mas restringe
  via API
* **Distribution**: Microsoft hosted marketplace + offline VSIX install

### 2.2 Photoshop / Adobe Plugins

* Manifest XML/JSON com `requiredPermissions` (network, fileSystem)
* User precisa **aprovar permissões** na primeira execução
* Code signing obrigatório no marketplace oficial

### 2.3 Excel Add-Ins

* `manifest.xml` com Capabilities + Hosts
* Trust Center bloqueia plugins não-confiáveis por default
* Centro de Confiabilidade exige opt-in explícito

### 2.4 Python Plugin Frameworks

| Framework | Pattern | Pros/Cons |
|-----------|---------|-----------|
| `importlib.metadata` entry points | Setup.cfg/pyproject.toml | Padrão Python, mas exige pip install |
| `pluggy` (pytest-style) | Hookspec/hookimpl | Mais rico, mas overhead de aprendizado |
| `stevedore` (OpenStack) | namespaces + entry_points | Pesado, prod-grade |
| Custom (current) | Decorators + glob | Simples, controlamos toda a lifecycle |

**Decisão**: manter o custom (decorators) e adicionar manifest YAML
+ schema Pydantic. Não migrar para entry_points porque queremos
plugins **standalone** (não exigem `pip install` — drop em pasta).

## 3. Princípios de design para Olivas v1.5.0

1. **Privacy/segurança first**: plugins NÃO rodam até o usuário
   aprovar — mesmo plugins instalados. Manifest visível antes da carga.
2. **Standalone-friendly**: não exige `pip install`, não exige internet.
   Usuário pode receber `.zip` por email e instalar.
3. **Lifecycle persistido**: estado salvo em `~/.olivas/plugins/state.json`
4. **PTW-like UX**: dialog 3 tabs (Installed / Available / Settings),
   ações claras (Install / Enable / Disable / Uninstall)
5. **Builtin catalog**: 3 plugins de exemplo embarcados (não exige
   internet) demonstrando capacidades.
