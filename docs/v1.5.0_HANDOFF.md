# v1.5.0 HANDOFF — Plugin Marketplace

**Data**: 2026-04-29

## 1. Resumo executivo

Estende o foundation v0.105.0 (decorators + bare-py discovery) com
sistema **profissional** de plugins:

* Manifest YAML obrigatório (Pydantic schema)
* 7 categorias × 11 permissões whitelist
* Security gate (SHA256 + version compat + permissions)
* Lifecycle persistido em `state.json`
* UI marketplace 3 tabs
* 3 builtin plugins demonstrando capacidades
* Privacy first: auto-load somente plugins enabled

## 4. Sprints executadas (TDD por sub-sprint)

### A — Manifest schema (Pydantic) ✅ 14 testes
* `PluginPermission` enum: 11 valores (studies/equipment/renderers/
  exporters/postprocessors/validators/catalog_specs + filesystem.read/
  write + network + subprocess)
* `PluginCategory` enum: 7 valores
* `PluginManifest` com validators de semver + regex de name
* Helper `is_compatible_with_olivas(version)`

### B — Discovery v2 + Lifecycle ✅ 9 testes
* `discover_plugins_v2(builtin/user/project)` com source label
* Precedência builtin > installed > project + warning em conflito
* `LifecycleState` com state.json schema_version 1.0
* `auto_load_enabled_plugins()` — só carrega enabled

### C — Security ✅ 10 testes
* `compute_sha256` chunked (arquivos grandes)
* `verify_sha256` case-insensitive
* `check_permissions_supported` contra whitelist enum
* `install_plugin` atômico (tmp + rename)
* `uninstall_plugin` rmtree

### D — UI Marketplace dialog ✅ 6 testes
* QDialog 1100×720 com QTabWidget (3 tabs)
* Tab 1: 4 ações (Habilitar/Desabilitar/Detalhes/Desinstalar)
* Tab 2: empty state explicativo (catálogo remoto vem em v1.5.1)
* Tab 3: paths + opções + stats
* QMessageBox de confirmação para enable (mostra permissões) e
  uninstall

### E — Builtin catalog ✅ funcional (verificado por discovery)
* `solar_pv_yield`: yield anual NREL Sandia (Brasil)
* `nbr_5410_validator`: queda V + FC + proteção
* `csv_exporter`: append CSV BR (delimitado por ;)

### F — Menu wiring + startup discovery ✅
* Menu: "Ferramentas → 🧩 Plugin Marketplace..."
* `MainWindow.__init__`: `auto_load_enabled_plugins()` no final
* Console panel mostra "v1.5.0: N plugin(s) carregado(s)"
* Backward compat: `_on_show_plugins` (v1.0.2) preservado

### G — Bump + handoff ✅
* `version.py`: 1.4.5 → 1.5.0 + changelog
* Este handoff doc

## 5. User testing gate v1.5.0 (5 passos antes de v1.5.1)

1. ✅ Abrir Olivas → Ferramentas → 🧩 Plugin Marketplace
2. ✅ Tab "Instalados": ver 3 builtin plugins (solar/NBR/CSV) com
   ícone ⚪ (disabled by default — privacy first)
3. ✅ Selecionar `solar_pv_yield` → clicar **Habilitar** → ver
   QMessageBox com permissões → confirmar → ícone vira 🟢 +
   título "Habilitado: solar_pv_yield"
4. ✅ Reabrir Olivas → console panel mostra "v1.5.0: 1 plugin(s)
   carregado(s) automaticamente: solar_pv_yield"
5. ✅ Verificar `~/.olivas/plugins/state.json` foi criado com
   `enabled: true` para o plugin habilitado

Após ✅ visual dos 5 passos, sigo para **v1.5.1 — DAPPER Demand
Load Library** (20+ NEC categorias) com mesma disciplina.

## 6. Anti-alucinação validado

* Cada Sprint tem TDD canônico antes do código
* `register_study`, `register_equipment`, `discover_plugins`
  v0.105.0 **não modificados** (testes existentes continuam verde)
* Manifest schema validado por Pydantic (não permite typos em
  permissions/category — enum-only)
* SHA256 testado com tampering simulado
* Install rejeita: manifest inválido, version mismatch, permission
  desconhecida, hash mismatch
* UI testes sem QMessageBox bloqueante (paridade lição v1.4.4 G)
