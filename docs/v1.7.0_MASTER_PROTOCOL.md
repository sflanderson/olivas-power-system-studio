## 1. As 5 garantias do Master Protocol

### 1.1 Auditar

**Antes** de qualquer mudança, fazer audit explícito do estado atual:

* Para cada feature alvo: ler arquivos existentes (Read completo), documentar
  o que já existe, o que falta
* Citar paths absolutos + LOC + funções públicas
* Documento dedicado: `vX.Y.Z_BACKLOG_AUDIT.md`

### 1.2 Registrar

**Durante** a implementação, manter trilha de auditoria:

* `TodoWrite` com 1 item in_progress por vez
* Cada Sprint termina com mark `completed` ou criação de novo item
  pendente (nunca sumir mudanças)
* Documentos versionados (audit + design + handoff)

### 1.3 Anti-alucinação

* Cada fórmula com fonte primária citada (norma + seção + equação)
* Cada teste com valor numérico tem comentário de referência
* Sem golden value publicado: `@pytest.mark.skip` ao invés de inventar
* Não substituir comportamento real por intuição (ex: lição
  Doughty-Neal v1.6.0)

### 1.4 Anti-crash, anti-perda de funções, anti-regressão

* **Read-then-Edit** sempre (nunca Write em arquivo existente)
* Adições > modificações; arquivos novos > edits cirúrgicos
* Regression sweep antes e depois de cada Sprint
* Se algum teste quebrar: **REVERTER** (file restore do snapshot) e
  investigar
* Lista TRAVADA de arquivos que NÃO podem ser tocados (anti-perda
  declarada explicitamente)

### 1.5 Ponto de restauração

* **Antes** de iniciar a release: snapshot completo de `app/` e `tests/`
  em `restore_points/<versao>_baseline/`
* Snapshot é **read-only reference** — não é deletado mesmo após
  release final
* Se algo der errado em qualquer Sprint: `cp -r snapshot/ app/` para
  reverter
* `restore_points/` versionado, não trackeado para git (sem .git aqui)
