## 3. Sprints

### Sprint A — CRDT core ✅ (19 testes)
NEW `app/collab/crdt.py` (~280 LOC) + `__init__.py`:

**LamportClock** (Lamport 1978 §3):
- `tick()` — incrementa
- `observe(remote_t)` — sincroniza com remoto: max(local, remote)
- `now()` — peek sem incrementar

**LWWRegister** (Last-Write-Wins):
- `set(value)` — carimba com (timestamp, node_id)
- `merge(other)` — maior (timestamp, node_id) lexico wins
- Idempotent (merge consigo = no-op)

**ORSet** (Observed-Remove Set, Shapiro 2011 §3.3.5):
- `add(element)` — cria nova tag única (node_id, seq)
- `remove(element)` — move tags atuais para tombstone
- `merge(other)` — union de pairs filtrada por tombstones
- Concurrent add+remove → add wins (semantics formal)

**CRDTOperation** (event sourcing):
- Dataclass frozen com (op_type, target_id, value, node_id, timestamp)
- Replay em qualquer ordem produz mesmo state final

## 7. Limitações declaradas v3.0.0 CRDT (anti-alucinação)

* **Sem network transport**: CRDTs operam em memória; sync peers
  exige camada network adicional (deferred)
* **Sem persistence**: state em RAM; serialization JSON deferred
* **Sem tombstones GC**: OR-Set tombstones acumulam (memory leak
  em sessões longas — deferred v3.1+)
* **Sem integração schematic**: CRDT primitives prontos mas
  ainda não wired ao PpEditor (deferred v3.0.x)

CRDT v3.0.0 é **foundation**; integração com schematic editor é
próxima fase.
