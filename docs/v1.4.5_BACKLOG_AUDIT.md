### Padrão 1 — Navegação interna ("Go To"), sem importadores externos enganosos

PTW Userguide §4 (lines 2370-2411) e Tutorial (line 177): toda transição
entre módulos usa o verbo **"Go to X"** (`Go to Component Editor / TCC /
Equipment Evaluation / Coordination Evaluation / Data Visualizer`).
**Nunca** existe rótulo `"Load External X"` ou `"Import from Y"` no menu
principal — toda integração é interna ao mesmo `*.PRJ`.

### Padrão 2 — Plots: aspect ratio toggleable + multi-curve em 1 viewport

CAPTOR §1.4.6 (lines 607-621): *"To create more room for coordination,
you may want to toggle the Fixed Aspect Ratio off and then drag the right
border of the TCC Drawing viewport"*. CAPTOR mostra **um único plot
log-log** com **múltiplas curvas sobrepostas**. Subplots empilhados
(stacked) são **raros** no PTW — quando inevitáveis, vêm via abas (TCC1,
TCC2 — Tutorial line 1244).

### Padrão 3 — Análises gateadas por seleção de componente (universal)

Equipment Evaluation §1.2 (`Reference-EquipmentEvaluation.pdf` line
137-143): *"Run > Failed Input Evaluation is available when the
Component Editor or a One-line Diagram is the active window"*.

Coordination Evaluation §3.4 (lines 761-765): right-click no componente
do oneline → `Go To Coordination Evaluation` → *"the selected component
will already be shown and selected"*.

Userguide tem **dezenas** de ocorrências da frase *"Available only when
X is open/selected"* (lines 2185-2233) — itens **acinzentados** (greyed)
quando o pré-requisito não está satisfeito, com tooltip explicando.

### Padrão 4 — PTW NUNCA abre plot view vazia sem prerequisites

CAPTOR §1.2.1 (lines 392-405): *"Preparing for Coordination"* —
pré-requisitos **numerados**: build oneline → run load flow + short-
circuit → gather library data → THEN open TCC.

Datablock Reports (Userguide lines 6314-6346): quando vazio mostra
mensagem textual: *"If the Datablock Report spreadsheet appears empty
when you run the Datablock Report command, either no Datablock Format
has been applied... or that no datablock is defined for that component
type"*.

**Não há "View > Plots" no PTW.** O usuário invoca a análise primeiro;
a view é criada **populada**.

## 2. Issues confirmados na Olivas v1.4.4

### Issue 1 — Menção PTW enganosa 🔴 CRÍTICO

Botão `"📂 Carregar JSON (PTW)"` na linha 117 de
`ct_saturation_dialog.py` + comentários em 3 docstrings + tab no
`equipment_library_dialog.py`. **Olivas não integra com PTW**, apenas
lê um JSON exportado pelo PTW (formato compatível). Rótulo é
publicidade enganosa.

### Issue 2 — Layout do dialog CT-SAT 🔴 CRÍTICO

Screenshot do user mostra:
* Título "Distorção da Forma de Onda" (subplot 2) **sobrepondo eixo X
  do subplot 1** (Fluxo)
* Form section ocupa ~1/3 da janela vertical → plots ficam comprimidos
* `fig.tight_layout()` insuficiente — precisa `constrained_layout=True`
  ou `subplots_adjust(hspace=0.4)`
* Janela 1200×850 mas plots renderizando com hspace default

### Issue 3 — Workflow desacoplado do canvas 🔴 CRÍTICO

Estado atual: menu `Análise > 🔍 Saturação de TC` abre o dialog
**sempre**, sem checar se há TC selecionado. Defaults didáticos
preenchem campos, então o usuário **nunca percebe que deveria ter
selecionado um TC primeiro**. Anti-pattern PTW.

Componente CT já existe em `app/preprocessor/catalog_specs/CT.ocomp`
com 10 properties (tag, ratio_pri, ratio_sec, classe, c_rating_V,
rs_ohm, rb_ohm, kr, t_relay_ms, t_breaker_ms) — mas o dialog não
consome essas properties.

### Issue 4 — Menu Visualizar > Gráficos sem propósito 🟡 MODERADO

`main_window.py` linhas 732-748: 4 actions criam docks via
`_ensure_plot_dock()`. Cada dock é uma classe (`PowerFlowVoltageProfileDock`,
`ScContributionPieDock`, `TccCurveOverlayDock`,
`MonteCarloHistogramDock`) que **abre vazia** se a análise prerequisito
nunca rodou. Usuário não sabe:
* Que análise alimenta cada gráfico
* Como populá-la
* Qual a ordem correta
