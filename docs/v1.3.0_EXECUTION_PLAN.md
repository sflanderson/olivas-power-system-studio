## Objetivo

Atingir paridade com PTW Power*Tools nos módulos de **avaliação automática**:

1. **Coordination Evaluation Rule Engine** (regras NEC 110.10 + IEEE 242 + NBR aplicadas a TCCDevices)
2. **Equipment Evaluation Dashboard** (9 critérios automáticos: rating × duty)

Após v1.3.0, Olivas terá:
- Engenharia: `ferramenta gera laudo "Pass/Warning/Fail" automaticamente, sem o engenheiro precisar verificar manualmente cada regra`
- Auditoria: `ferramenta produz dashboard tabular consumível por gerente / cliente`

Isto fecha o gap "PTW gera laudo, Olivas calcula mas não decide".

## Escopo

### Fase A — Coordination Rule Engine (estimativa: 1500 LOC + 50 testes)

**A.1 — Rule data model** (~300 LOC + 12 testes)
- `Rule` dataclass: id, description, applicable_to (TCCDevice/DamageCurve/Bus), eval_func, severity
- `RuleSet` container: agrupa regras por norma/categoria
- `RuleResult` dataclass: rule_id, status (PASS/WARN/FAIL), message, citation, target_id

**A.2 — Built-in rules library** (~600 LOC + 20 testes)
- Arquivo `app/postprocessor/coord_rules_builtin.py`
- Rules NEC 110.10:
  - Motor Relay LTPU 51 = 115%-125% FLA (com SF≥1.15)
  - Motor LTPU 49 thermal = 100%-200%
  - LV XFMR primário FLA<2A → LTPU 100%-300%
  - LV XFMR FLA<9A → 100%-167%
  - LV XFMR FLA≥9A → 100%-125%
  - HV XFMR Z≤6% → LTPU 100%-600%
  - Cable LTPU 51 cutoff 80% damage curve
  - Generator LTPU 51V no-restraint 100%-200%
  - Capacitor LTPU 105% FLA
- Rules IEEE 242 §15.10.1:
  - Δt mínimo digital 0.25s
  - Δt mínimo electromechanical 0.40s
- Rules NBR (suplementares à NEC):
  - Motor B2 conforme ABNT
  - Cabo NBR 5410 §6.5.4

**A.3 — Engine + dispatcher** (~400 LOC + 15 testes)
- `RuleEngine` class
- `apply_rule(rule, target)` → RuleResult
- `apply_ruleset(ruleset, targets)` → list[RuleResult]
- `evaluate_project(project)` → groupby severity (PASS/WARN/FAIL)
- Filtros: por device type, por norma, por severity

**A.4 — Plugin support** (~200 LOC + 8 testes) — opcional, pode ficar v1.3.1
- `@register_rule(ruleset_name)` decorator
- Discovery automático

### Fase B — Equipment Evaluation Dashboard (estimativa: 1000 LOC + 35 testes)

**B.1 — Evaluation criteria model** (~250 LOC + 10 testes)
- `EvaluationCriterion` enum (9 PTW criteria)
- `EvaluationResult` dataclass

**B.2 — 9 critérios PTW implementados** (~500 LOC + 18 testes)
- Voltage Rating cables/PD vs nominal bus
- Interrupting Fault Duty vs Rating
- Asymmetrical Duty vs Asym Rating
- Load Flow Current vs Continuous Rating
- Design Load vs Continuous
- Generator Size vs Load Flow Output
- Bus Voltage Drop vs limit
- Branch Voltage Drop
- Device Voltage Drop

**B.3 — Dashboard generation** (~250 LOC + 7 testes)
- HTML report tabular Pass/Fail
- Color coding (verde/amarelo/vermelho)
- Excel export (csv simples sem deps)

## Riscos antecipados

| Risco | Mitigação |
|---|---|
| Regras NEC 110.10 % values são tabela vasta | Cobrir 10-15 mais usados; outros via plugin |
| Confusão Rule vs check_device_coordination | Rules são REGRAS DE NEGOCIO (engenharia); coord check é cálculo numérico |
| Engine vira god-object | Separar em RuleSet + RuleEngine + Dispatcher |
| Falsos positivos em rules sem device adequado | Cada Rule declara `applicable_to` explicitly |

---

## Glossário

| Termo | Significado |
|---|---|
| **Rule** | Função pura de engenharia: `(target) → PASS/WARN/FAIL` |
| **RuleSet** | Coleção de rules de mesma origem (NEC, IEEE 242, NBR) |
| **RuleResult** | Output de uma rule aplicada a um target específico |
| **RuleEngine** | Orquestrador que aplica RuleSets a projetos inteiros |
| **EvaluationCriterion** | 9 critérios PTW de Equipment Evaluation |
| **Dashboard** | Visualização tabular Pass/Fail consumível por humanos |
