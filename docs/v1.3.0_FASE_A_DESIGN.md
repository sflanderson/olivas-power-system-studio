## Problema

Em PTW Power*Tools "Coordination Evaluation" (add-on que requer DAPPER + CAPTOR), o usuário roda o módulo e recebe **dashboard tabular** de Pass/Warning/Fail por equipamento, com regras configuráveis tipo:

```
Motor Relay 51 LTPU = 115%-125% FLA (NEC 110.10) ✓ PASS
Motor 49 thermal = 100%-200% FLA            ⚠ WARN (atual 95%)
LV XFMR 2W LTPU primário (FLA<9A) = 100%-167% × FLA  ✓ PASS
Cable damage 80% rule (NBR 5410)            ✗ FAIL
```

Olivas v1.2.0 tem o **cálculo numérico** (`check_device_coordination` da β.3) mas não tem **regras de engenharia** que dizem "esse setting está dentro/fora do range aceitável".

A Fase A entrega esse engine.

---

## Solução: Rule + RuleSet + RuleEngine

### A.1 — Data model

```python
class RuleSeverity(str, Enum):
    PASS = "pass"
    WARN = "warn"
    FAIL = "fail"
    NOT_APPLICABLE = "n/a"

@dataclass(frozen=True)
class RuleResult:
    rule_id: str
    target_id: str               # device_id, cable_id, etc.
    severity: RuleSeverity
    message: str                 # texto humano-legível
    citation: str                # norma + página
    evaluated_value: Optional[float] = None
    expected_range: Optional[tuple[float, float]] = None

@dataclass(frozen=True)
class Rule:
    rule_id: str                 # "NEC-110.10-MOTOR-51-LTPU"
    description: str
    citation: str                # "NEC 110.10 + IEEE 242 §9.5.4"
    applicable_to: tuple[type, ...]  # (TCCDevice,) ou (CableDamageCurve,)
    eval_func: Callable          # (target, context) → RuleResult

@dataclass(frozen=True)
class RuleSet:
    name: str                    # "NEC 110.10 Motor Protection"
    rules: tuple[Rule, ...]
    norm_reference: str
```

**Decisões**:
- Frozen dataclass para imutabilidade (consistente com α/β/γ)
- `applicable_to` é tuple de tipos para isinstance check
- `eval_func` é uma função pura — facilita teste e plugin
- `RuleResult` carrega `evaluated_value` e `expected_range` para auditoria forense
- Citation explícita em Rule e RuleResult

### A.2 — Built-in rules library

Arquivo `app/postprocessor/coord_rules_builtin.py` com **15 regras** distribuídas em 3 RuleSets:

#### RuleSet "NEC 110.10 + IEEE 242"
1. `NEC_MOTOR_51_LTPU` — pickup 51 = 115%-125% × FLA (com SF≥1.15)
2. `NEC_MOTOR_49_THERMAL` — pickup 49 = 100%-200% × FLA
3. `NEC_MOTOR_50_INST` — pickup 50 ≥ 5×FLA (sem operar em starting normal)
4. `NEC_LV_XFMR_2W_PRI_LTPU_SMALL` — FLA<9A → 100%-167%
5. `NEC_LV_XFMR_2W_PRI_LTPU_LARGE` — FLA≥9A → 100%-125%
6. `NEC_HV_XFMR_LTPU_LOW_Z` — Z≤6% → 100%-600%
7. `NEC_GEN_51V_NO_RESTRAINT` — 100%-200%
8. `NEC_CAPACITOR_LTPU` — 105% × FLA típico
9. `IEEE_242_DT_DIGITAL` — Δt mínimo 0.25s (digital)
10. `IEEE_242_DT_ELECTROMECH` — Δt mínimo 0.40s (eletromecânico)

#### RuleSet "NBR / ABNT"
11. `NBR_5410_CABLE_DAMAGE_80PCT` — proteção 51 cutoff em 80% damage curve
12. `NBR_5410_MOTOR_THERMAL` — equivalente NEC 110.10 motor 49

#### RuleSet "IEEE C57.109"
13. `IEEE_C57_109_XFMR_FREQUENT_THRU_FAULT` — proteção upstream sobre damage frequent
14. `IEEE_C57_109_XFMR_INFREQUENT` — idem para infrequent

#### RuleSet "Best Practices"
15. `BP_MOTOR_50_NO_TRIP_ON_INRUSH` — INST > 8×FLA (evita trip em inrush)

Cada regra é uma função de assinatura padrão:

```python
def rule_NEC_motor_51_ltpu(target: TCCDevice, context: dict) -> RuleResult:
    """
    NEC 110.10 + IEEE 242 §9.5.4: Motor relay 51 LTPU deve estar
    entre 115% e 125% × FLA (com SF≥1.15).

    Cita: IEEE 242 §9.5.4 Tabela 9-2.
    """
    # Extrai FLA do context
    fla = context.get("fla_A")
    if fla is None:
        return RuleResult(
            rule_id="NEC-MOTOR-51-LTPU",
            target_id=target.device_id,
            severity=RuleSeverity.NOT_APPLICABLE,
            message="FLA não fornecido no context",
            citation="IEEE 242 §9.5.4",
        )

    # Encontra segment 51 LT
    seg_51 = next((s for s in target.segments
                   if "51" in s.segment_id and hasattr(s, "pickup_A")), None)
    if seg_51 is None:
        return RuleResult(
            rule_id="NEC-MOTOR-51-LTPU",
            target_id=target.device_id,
            severity=RuleSeverity.NOT_APPLICABLE,
            message="Device não tem segment 51 LT",
            citation="IEEE 242 §9.5.4",
        )

    pickup = seg_51.pickup_A
    pickup_pct_fla = pickup / fla * 100.0
    if 115.0 <= pickup_pct_fla <= 125.0:
        sev = RuleSeverity.PASS
        msg = f"51 LTPU = {pickup_pct_fla:.1f}% FLA (range 115-125% OK)"
    elif 100.0 <= pickup_pct_fla < 115.0 or 125.0 < pickup_pct_fla <= 140.0:
        sev = RuleSeverity.WARN
        msg = f"51 LTPU = {pickup_pct_fla:.1f}% FLA (fora do range 115-125%, mas tolerável)"
    else:
        sev = RuleSeverity.FAIL
        msg = f"51 LTPU = {pickup_pct_fla:.1f}% FLA (FORA do range NEC 110.10)"

    return RuleResult(
        rule_id="NEC-MOTOR-51-LTPU",
        target_id=target.device_id,
        severity=sev,
        message=msg,
        citation="NEC 110.10 + IEEE 242 §9.5.4 Tabela 9-2",
        evaluated_value=pickup_pct_fla,
        expected_range=(115.0, 125.0),
    )
```

## Riscos antecipados

| Risco | Mitigação |
|---|---|
| FLA não disponível no context | Rule retorna NOT_APPLICABLE explícito |
| Devices sem segments esperados | Rule retorna NOT_APPLICABLE |
| Rules acopladas a TCCDevice spec | applicable_to + isinstance check |
| Rules conflitantes (NEC vs NBR) | RuleSet separados; engine reporta ambos |
| Hardcoding de % values sem fonte | Citation obrigatória + comentário com manual page |
