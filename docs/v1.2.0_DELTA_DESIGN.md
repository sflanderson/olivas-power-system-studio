# v1.2.0 Fase δ — Design Document (GUI Integration)

**Sprint**: δ (GUI integration de Device + DamageCurve no coordinogram)
**Plano pai**: `docs/v1.2.0_EXECUTION_PLAN.md`
**Pré-requisito**: Fases α + β + γ + audit consistência limpos
**Princípio**: documentar decisão de design ANTES de codar; preservar GUI v1.1.0 funcional.

## Problema

A Fase β entregou `TCCDevice` + `MultiFunctionRelay`. A Fase γ entregou 3 damage curve classes. **Mas o widget de coordenograma (`tcc_coordinogram.py`) ainda só aceita TCCCurve e FuseTCCCurve do v1.1.0** — não conhece nem renderiza:

- Multi-function devices (mostraria só 1 segment, não o composite)
- Damage curves (não há overlay vermelho como em PTW CAPTOR)
- Violation marker quando proteção cruza damage

A Fase δ fecha o ciclo "backend completo + GUI funcional" da v1.2.0.

---

## Solução

### Estratégia: extensão dispatch-by-type sem breaking change

Em v1.1.0, `_draw_all` já faz `isinstance(curve, FuseTCCCurve)` dispatch. Vou estender:

```python
def _draw_all(self):
    for idx, curve in enumerate(self._curves):
        color = _COLORS_BY_INDEX[idx % len(_COLORS_BY_INDEX)]
        if isinstance(curve, FuseTCCCurve):       # v1.1.0
            self._draw_fuse_curve(...)
        elif isinstance(curve, TCCDevice):         # δ.1 NEW
            self._draw_device(...)
        elif isinstance(curve, (CableDamageCurve,
                                 TransformerThroughFaultCurve,
                                 MotorThermalCurve)):  # δ.2 NEW
            self._draw_damage_curve(...)
        else:                                      # legacy TCCCurve
            self._draw_relay_curve(...)
```

Isso preserva compatibilidade: tudo o que funcionava em v1.1.0 continua funcionando.

### δ.1 — Adapter TCCDevice no widget

**Helper `_draw_device(ax, idx, device, color)`**:
- Plota o **composite envelope** (uma curva) com cor sólida
- Label do plot inclui device_id + manufacturer/model
- Para cada segment enabled, desenha uma **vertical pickup line tracejada** na sua cor (visualmente identifica os 50/51/49/87)
- Drag-drop NÃO suportado em devices (segments individuais não exposed via composite — para alterar TMS, edita o segment via API e re-cria o device)

### δ.2 — Damage curves overlay

**Helper `_draw_damage_curve(ax, idx, damage, color)`**:
- Cor: vermelho `#C0392B` (paleta PTW corporativa, mesma da v1.1.0)
- Linestyle: tracejado denso `(0, (5, 2))` (visualmente "perigo")
- Linewidth: 1.5 (mais discreto que proteção sólida 2.0)
- Zorder baixo (3) — proteção fica por cima
- Hatching opcional (área acima da curva = "danger zone") — explorar se tempo permitir

**Detecção do tipo**:
```python
DAMAGE_CLASSES = (
    CableDamageCurve,
    TransformerThroughFaultCurve,
    MotorThermalCurve,
)
```

### δ.3 — Violation marker (cruzamento proteção × damage)

**Algoritmo simples**:
1. Para cada par (protection, damage) na lista:
2. Avalia em N pontos (default 50, log-spaced) entre `i_min` e `i_max`
3. Conta pontos onde `t_protection(I) > t_damage(I)` (cruzamento crítico)
4. Se ≥1 ponto cruzou: marca o cruzamento mais à esquerda (corrente menor = pior caso) com:
   - Marker vermelho (X)
   - Annotation "⚠ VIOLATION cable damage"
   - Halo translúcido na zona afetada

**Pseudo-code**:
```python
def _detect_violations(self, ax):
    protections = [c for c in self._curves
                   if isinstance(c, (TCCDevice, MultiFunctionRelay))]
    damages = [c for c in self._curves
               if isinstance(c, DAMAGE_CLASSES)]
    for prot in protections:
        for dmg in damages:
            self._check_protection_vs_damage(ax, prot, dmg)
```

## Riscos antecipados e mitigação

| Risco | Mitigação |
|---|---|
| Quebrar drag-drop existente | Tests específicos (continuar funcionando para TCCCurve) |
| matplotlib QtAgg em CI sem display | Reusa pattern dos tests v1.1.0 (QApplication mock-based) |
| isinstance order matters (TCCDevice é subclass de nada, mas FuseTCCCurve precisa vir primeiro?) | Documentar ordem explícita |
| Cores conflitantes (proteção idx=1 = laranja, damage = vermelho) | Damage tem cor FIXA #C0392B independente de idx |
| Violations false-positive em low-current | Usar threshold mínimo (só report se cruz acima de I=Inom·1.5) |
| Performance: 5 devices × 200 pontos cada = 1000 plot pts | Aceitável (< 100ms render típico) |
| Subclass MultiFunctionRelay confundindo isinstance | `isinstance(curve, TCCDevice)` cobre ambos (Liskov) |

## Glossário (anti-confusão)

| Termo | Significado |
|---|---|
| **Adapter** | Função `_draw_*` que traduz entre tipo backend (Segment/Device/DamageCurve) e matplotlib artist |
| **Composite envelope** | min(t_segment) sobre todos enabled num device — uma única curva no plot |
| **Violation** | Cruzamento onde proteção lenta deixa damage acontecer antes do trip |
| **Zorder** | Camada matplotlib (alto = na frente). Proteção zorder 5, damage zorder 3 |
| **Drag-drop** | Mouse pressed em curva → arrastar muda TMS. Suportado: TCCCurve. NÃO suportado: FuseTCCCurve, TCCDevice, DamageCurve |
