## 4. Sprint v3.9.0 — Fault distance walker (B.4)

NEW `app/postprocessor/fault_distance_walker.py` (~280 LOC):

### Constants
* `DEFAULT_BREAKER_MIN_DELAY_S = 0.050` (50ms typical MV)
* `DEFAULT_X_D_SUBTRANSIENT_PU = 0.20` (sync machine)
* `DEFAULT_UTILITY_XD_PU = 1e-6` (utility ≈ infinite bus)

### Helpers
* `_classify_source_component(comp)` — UTIL/MOTOR/GEN → tipo
* `_read_motor_n_poles(comp)` — lê n_poles do MOTOR.ocomp (default 2)
* `_motor_speed_gradient(n_poles)` — IEC 60909-0:2016 §4.6.2 Tab 3:
  - 2-pole → 0.10
  - 4-pole → 0.05
  - 6+-pole → 0.02

### Core API
* **`find_nearby_sources(project, fault_bus_name, max_hops=2)`** —
  BFS Manhattan-based (300px ≈ 1 hop heuristic)
* **`auto_classify_fault_distance(project, fault_bus_name)`** →
  `FaultClassification` com:
  - `fault_distance` (NEAR/FAR per IEC 60909-0:2016 §3.7)
  - `suggested_breaker_min_delay_s`
  - `suggested_x_d_subtransient_pu`
  - `is_synchronous_motor`
  - `motor_speed_gradient_pu_per_s` (compat v3.7.0 B.3)
  - `nearby_sources: list[(name, type)]`
  - `notes` (human-readable explanation)

### Logic
- Synchronous motor / generator within max_hops → NEAR_TO_GENERATOR
- Only utility / induction → FAR_FROM_GENERATOR
- No source detected → FAR (default conservador)

**Tests**: 16 verdes (incluindo integration com `calculate_short_circuit`).

## 10. Anti-alucinação — limitações declaradas

### v3.8.2 D.3
1. **Datablock é texto estático** — não é live-updated quando user
   ajusta curves via dragging. Refresh manual reabrindo dialog.
2. **Settings tab tem apenas fault_current** — outros parâmetros
   (TMS multiplier, plot range) deferred v4.x.

### v3.9.0 B.4
1. **Manhattan distance é heurística** — 300 px ≈ 1 hop é aproximação
   visual, não topology-aware. Wire-graph BFS deferred.
2. **Xd''=0.20 fixed** — não le `MOTOR` properties para extrair
   Xd'' real (modelo síncrono). Refinement v4.x.
3. **Single dominant source** — múltiplas fontes próximas são listadas
   mas só a primeira influencia decision. IEC 60909-0 §4.5 multi-source
   aggregation deferred.

### v4.0.0-alpha geral
1. **alpha = NÃO production-ready** — milestone atingido tecnicamente,
   mas requer bateria de validation studies + user acceptance test.
2. **Cobertura PTW = 65%** (estimado) — não é literal 100% do PTW,
   mas paridade dos itens TIER 1 + roadmap inicial.
3. **Standards integration parcial** — IEC 60909, IEC 60076,
   IEEE 1366, IEEE 493, NBR 5410, NBR 17227 cobertos; outros
   (IEEE 1547, IEEE 519 harmonics deep) limitados.
