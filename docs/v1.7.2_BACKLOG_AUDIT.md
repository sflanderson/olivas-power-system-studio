## 1. Issue #1 — Pin positions invisíveis

### Diagnóstico

Componentes BREAKER, RELAY, CT (e outros) renderizam o símbolo
mas **não desenham marcadores visuais nos pin positions**.

Exemplo da screenshot:
* RELAY1: tem símbolo R em círculo + label "51" — pinos invisíveis
  nas posições (-30, 0), (30, 0), (0, -30), (0, 30)
* BREAKER1: símbolo quadrado + cruz — pinos invisíveis
* CT1: símbolo TC — pinos invisíveis

Usuário não sabe **onde clicar para iniciar uma wire**.

### Root cause

`ComponentItem.paint()` em `items.py` chama `self.renderer.paint(painter)`.
Os renderers em `ptw_symbols.py` desenham o símbolo mas nenhum
deles desenha pin dots.

### Fix

Adicionar `_paint_pin_dots(painter)` no `ComponentItem.paint()`
**após** o renderer.paint, dentro do mesmo método. Desenha
círculos pequenos (radius 2-3 px) nos `renderer.pin_positions()`
em cinza claro. Quando `isSelected()`: dots verdes para destaque.

Anti-perda: NÃO modifica nenhum dos 56 symbol renderers; apenas
adiciona ao paint do ComponentItem (1 file).

## 2. Issue #2 — Multi-drag desconecta wires

### Diagnóstico

Quando usuário seleciona múltiplos componentes (rubber band ou
Ctrl+click) e arrasta, **wires anexadas ficam fixas** em vez de
seguir os componentes.

### Root cause

`ComponentItem.mousePressEvent` captura `_anchor_snapshot` apenas
no item que recebeu o press event. Outros items selected entram
no drag via Qt selection-driven movement mas seus
`_anchor_snapshot` ficam vazios → `_sync_anchored_wires()`
return early.

### Fix

Em `mousePressEvent`, **propagar** o capture para todos os
ComponentItems selected na cena:

```python
def mousePressEvent(self, event):
    self._press_pos = (self.component.x, self.component.y)
    self._anchor_snapshot = self._capture_attached_anchors()
    self._anchor_before_endpoints = [...]

    # v1.7.2 fix: também captura para outros selected
    scene = self.scene()
    if scene and self.isSelected():
        for item in scene.selectedItems():
            if item is self:
                continue
            if isinstance(item, ComponentItem) and not item._anchor_snapshot:
                item._press_pos = (item.component.x, item.component.y)
                item._anchor_snapshot = item._capture_attached_anchors()
                item._anchor_before_endpoints = [...]

    super().mousePressEvent(event)
```

Anti-perda: edit aditivo (não modifica capture/sync existentes).

## 3. Issue #3 — Gráficos populate from cache não funciona

### Diagnóstico

v1.7.0 Sprint C adicionou `populate_from_cache()` em cada dock.
`_ensure_plot_dock()` no main_window chama populate quando dock
é criado.

**Problema 1**: `solve_power_flow()` é chamado em
`examples/stevenson_pf_3bus.py` e `validation/benchmarks.py` mas
**NUNCA no fluxo F5 do run_analysis_dialog**. Logo
`cache.has_pf()` sempre retorna False → empty state mantido.

**Problema 2**: quando dock já está aberto (criado em sessão
anterior) e usuário roda novo estudo, dock não atualiza
automaticamente.

### Fix

**Parte A**: hook nos study runners (SC, coord, arc-flash) para
chamar `_refresh_plot_docks()` no main_window após cache.set_X.

**Parte B**: `_refresh_plot_docks()` percorre todos os docks
existentes (`_plot_dock_pf_voltage`, `_plot_dock_sc_pie`, etc) e
chama `populate_from_cache()` neles.

**Parte C** (escopo travado): NÃO implementar PF no F5 dialog
nesta release — issue ortogonal. Power Flow continua via
`solve_power_flow()` API direta. Documentar gap.

Anti-perda: edit cirúrgico — adiciona método novo
`_refresh_plot_docks()` no main_window e hook nos 3 study handlers.
