## Problema

PTW Power*Tools "Equipment Evaluation" gera **dashboard tabular único** com 9 critérios automáticos por equipamento, indicando Pass/Fail por critério × % do rating utilizado.

Exemplo de saída PTW:

```
| Equipment   | V Rating | Int Duty | Sym Duty | Cont I | Design Load | V-drop |
|-------------|----------|----------|----------|--------|-------------|--------|
| BUS-MAIN    | ✓ PASS   | ✓ PASS   | ✓ PASS   | —      | —           | ✓ PASS |
| BREAKER-1   | ✓ PASS   | ⚠ 92%    | ✓ 78%    | ✓ 65%  | ✓ 70%       | —      |
| CABLE-F1    | ✓ PASS   | —        | —        | ⚠ 95%  | ✗ 110%      | ⚠ 4.5% |
```

Cada critério é uma comparação `duty / rating` com thresholds:
- `<70%` → PASS verde
- `70-100%` → WARN amarelo
- `>100%` → FAIL vermelho

Olivas v1.2.0+ tem:
- **EquipmentLibrary** com models (RelayModel/MotorModel/TransformerModel/BreakerModel)
- **Rule Engine** (Fase A) que pode ser reusado se modelarmos critérios como Rules
- **DamageCurves** (γ) para validação cable
- **TCCDevice** (β) para coordenação

A Fase B fecha o gap de "engenheiro precisa cruzar manualmente: tem rating × duty, agora dashboard".

### B.1 — EquipmentInstance + EvaluationReport data model

```python
@dataclass(frozen=True)
class EquipmentInstance:
    """
    Um equipamento físico com ratings (do model) + duty operacional.

    Diferente de EquipmentLibrary models (templates), esta é uma
    INSTÂNCIA num projeto específico com:
    - reference ao model (BreakerModel, etc.)
    - duty: dict com valores operacionais (I_load_A, I_fault_kA, V_drop_pct)
    """
    equipment_id: str
    equipment_type: str  # "breaker", "cable", "transformer", etc.
    rated_voltage_kV: float
    rated_continuous_A: float
    rated_interrupt_kA: float = 0.0
    rated_asym_kA: float = 0.0
    bus_voltage_kV: float = 0.0
    duty: dict = field(default_factory=dict)
```

Decisão: **NÃO reusar BreakerModel/MotorModel diretamente** — esses são templates de fabricante (datasheet), enquanto EquipmentInstance carrega duty operacional. Linkagem opcional via `model_ref: Optional[str]`.

```python
@dataclass(frozen=True)
class EvaluationReport:
    """Sumário de uma avaliação de um equipamento contra critérios."""
    equipment_id: str
    results: tuple   # tuple[RuleResult, ...]

    def passes_all(self) -> bool: ...
    def failures(self) -> list: ...
    def warnings(self) -> list: ...
```

### B.2 — 9 critérios como Rules

Cada critério vira um `Rule` em `equipment_eval_rules.py`:

| # | Rule ID | Aplicabilidade | Threshold |
|---|---|---|---|
| 1 | `EQ-VOLTAGE-RATING` | All | Rated_V ≥ Bus_V |
| 2 | `EQ-INTERRUPT-DUTY` | Breaker | Ik'' ≤ Interrupt_kA |
| 3 | `EQ-ASYM-DUTY` | Breaker | ip ≤ Asym_kA |
| 4 | `EQ-LOAD-FLOW-CURRENT` | Cable/Breaker | I_load ≤ Continuous_A |
| 5 | `EQ-DESIGN-LOAD` | Cable/Breaker | Design_load ≤ Continuous_A |
| 6 | `EQ-GENERATOR-CAPACITY` | Generator | I_load ≤ Gen_capacity_A |
| 7 | `EQ-BUS-VOLTAGE-DROP` | Bus | V_drop_pct ≤ 4% (NBR 5410) |
| 8 | `EQ-BRANCH-VOLTAGE-DROP` | Cable | V_drop_pct ≤ 4% |
| 9 | `EQ-DEVICE-VOLTAGE-DROP` | Breaker | V_drop_device ≤ 1% (típico) |

Cada rule retorna `RuleResult` (reusa data model A.1):
- `evaluated_value` = duty em % do rating
- `expected_range` = (0, 100)% para PASS estrito, (0, 70)% para PASS confortável

## Riscos antecipados

| Risco | Mitigação |
|---|---|
| EquipmentInstance vira god-object | Manter duty como dict opaco — flexibilidade |
| 9 critérios duplicam lógica | Helper `_pct_check(value, rating, warn_at)` |
| HTML difícil sem jinja2 | f-strings + CSS inline (boa prática) |
| Rules de Equipment misturadas com Coord Rules | Módulo separado (equipment_eval_rules.py) |
| Threshold WARN/FAIL ambíguo | Citar IEEE 242 ou best practice em cada rule |
