### Sprint 5 — KT / KG / KSO correction factors ✅ (parte de 18/18)

**Audit finding §D.2**: IEC 60909-0:2016 §6.3.3 (KT) e §6.6.2 (KG/KSO) ausentes.

**Fix em `app/standards/iec60909.py`** (3 funções novas):

```python
def transformer_correction_factor_KT(*, voltage_factor_c_max, x_T_pu) -> float:
    # IEC 60909-0:2016 §6.3.3 Eq. (12)
    # KT = 0.95 × cmax / (1 + 0.6 × x_T)
    return 0.95 * voltage_factor_c_max / (1.0 + 0.6 * x_T_pu)

def generator_correction_factor_KG(*, voltage_factor_c_max, x_d_subtransient_pu, cos_phi_rg=0.85):
    # IEC 60909-0:2016 §6.6.2 Eq. (17)
    # KG = cmax / (1 + xd'' × sin(φrG))
    sin_phi = math.sqrt(1.0 - cos_phi_rg ** 2)
    return voltage_factor_c_max / (1.0 + x_d_subtransient_pu * sin_phi)

def motor_correction_factor_KSO(*, voltage_factor_c_max, x_M_subtransient_pu, cos_phi_motor=0.83):
    # IEC 60909-0:2016 §6.7
    sin_phi = math.sqrt(1.0 - cos_phi_motor ** 2)
    return voltage_factor_c_max / (1.0 + x_M_subtransient_pu * sin_phi)
```

Validação golden:
- KT(c=1.10, x=0.05) → **1.0146** (0.95 × 1.10 / 1.030)
- KG(c=1.10, xd''=0.20, cosφ=0.85) → **0.995**
- KSO(c=1.10, xM''=0.20, cosφ=0.83) → **0.989**

## 7. Anti-alucinação — limitações declaradas

1. **Sprint 1 — análise unbalanced ainda usa `analyze_unbalanced_pf` placeholder** —
   o solver real 3-φ N-R com Y_012 ainda é deferido (audit §B.1). Demo mode
   visualmente correto, mas não é solver real.

2. **Sprint 3 — IEEE 14-bus reduzido a 5-bus subset** — fixture infrastructure
   para 14-bus completo deferred a v3.3.1+.

3. **Sprint 4 — `build_equipment_from_project` é heurístico** — extrai ratings de
   strings tipo "15 kV". Para projetos com ratings em campos estruturados
   (`.ocomp` schema), v3.3.x pode adicionar parser estruturado.

4. **Sprint 5 — KT/KG/KSO não integrados a `calculate_short_circuit`** —
   funções existem mas o caller deve aplicá-las explicitamente
   (`Z_TK = KT × Z_T`). Integração automática deferred.

5. **PowerFlowDialog ainda é 2-bus only** (audit §A.3) — refactor topologia
   N-bus deferred. Para projetos N-bus, use API programática.

6. **EquipmentEvalDialog não auto-extrai do PpProject** — `set_equipments()`
   precisa ser chamado explicitamente. Wiring automático deferred.
