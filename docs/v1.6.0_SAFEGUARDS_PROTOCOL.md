# v1.6.0 — Protocolo de Salvaguardas (anti-alucinação + anti-perda de
dados + anti-funcionalidade acidental)

> Pedido formal do usuário antes de v1.6.0: **"seguir mantendo qualidade
> e auditoria. anti-alucinação, anti-perda de dados e funcionalidade
> acidental"**.
>
> Este documento formaliza as 3 garantias como **regras invioláveis**
> aplicáveis a v1.6.0 e releases subsequentes (v1.7.0 / v2.0.0).

---

## 1. Anti-alucinação — regras

### 1.1 Cada fórmula tem fonte primária citada

* Cada `.py` novo deve ter docstring com **citação literal**: norma
  + seção + página/equação. Não basta dizer "IEEE 1584-2018".
  Tem que ser "IEEE 1584-2018 §6.5 Equation 8".
* Para papers (Doughty-Neal, Stokes-Oppenheim): citar autor + ano +
  journal/conference + DOI quando disponível. Se não tenho acesso ao
  paper original, citar **standard secundário que reproduz** (ex:
  "IEEE 1584-2002 Annex B reproduz Doughty-Neal-Floyd 2000").

### 1.2 Cada fórmula tem golden test

* TDD canônico **com valores publicados** — não inventados.
* Cada teste tem comentário: "Reference: <fonte>, expected E_J/cm² = X".
* Se não há valor publicado, marcar `@pytest.mark.skip(reason=
  "no golden value available")` em vez de inventar.

### 1.3 Boundary explícito do que NÃO está implementado

* No README de cada módulo: seção "Limitações declaradas".
* Ex: NESC 2023 é table-based, **não** calcula incident energy
  cal/cm² — declara isso explicitamente.

## 2. Anti-perda de dados — regras

### 2.1 Read-then-Edit (nunca Write em arquivo existente)

* **Antes** de editar `arc_flash.py`/`epri_arc_flash.py`/etc:
  1. Read completo
  2. Identificar pontos de extensão (extensão pode ser nova função
     adicionada, não substituição)
  3. Edit cirúrgico apenas no ponto identificado

* **Nunca** chamar `Write` em arquivo que já existe (a menos que
  reescrever 100% do arquivo seja a única opção, com aprovação
  explícita do usuário).

### 2.2 Backward compat tests verde antes e depois de cada Sprint

* Antes de cada Sprint: rodar `tests/test_pp_arc_flash.py`,
  `test_pp_arc_flash_pro.py`, `test_pp_v0_101_0_arc_flash_hv.py`,
  `test_pp_v1_4_0_arc_flash_label_*.py` — **devem passar**.
* Depois de cada Sprint: re-rodar — **devem continuar passando**.
* Se algum quebrar: **REVERTER** edit, investigar, refazer.

### 2.3 Adições, não modificações

* Cada novo standard fica em **arquivo novo dedicado** em
  `app/standards/`:
  - `nesc_2023_arc_flash.py` (NEW)
  - `doughty_neal_arc_flash.py` (NEW)
  - `dc_arc_flash.py` (NEW)
  - `csa_z462_arc_flash.py` (NEW)

* Comparison module (`arc_flash_comparison.py`) também é NEW.

* `arc_flash.py` (IEEE 1584 — 495 LOC) e `epri_arc_flash.py`
  (308 LOC) **NÃO são tocados**. Já estão verde, paridade testada.

## 3. Anti-funcionalidade acidental — regras

### 3.1 Escopo travado por sprint no design doc

* Cada Sprint tem **lista exata** de:
  - Arquivos NOVOS criados
  - Arquivos EXISTENTES editados (com nº de linhas mexidas)
  - Funções/classes adicionadas (assinatura)

* Mudanças fora do escopo: **REVERTER** ou **adicionar item ao
  backlog v1.6.1+** explicitamente. Não slipar dentro da release.

### 3.2 Diff review antes de cada commit

* Antes de marcar Sprint como completo: `git diff --stat` para revisar
  arquivos tocados. Se aparecer algo não esperado: investigar.

### 3.3 TodoWrite com 1 item in_progress por vez

* Se aparecer ideia "também posso melhorar X": criar item separado
  no Todo, **não** inserir na sprint atual.

---

## 4. Regressão obrigatória

Antes de bump de versão:

* Sweep completo: `tests/` — **todos verde**
* Sweep arc-flash específico (5 test files anteriores) — **todos verde**
* Manual smoke: import de cada novo módulo + chamada de função-stub

---

## 5. Anti-pattern a evitar (lições passadas)

* ❌ Substituir `arc_flash.py` por uma versão "unified" — quebra
  testes v0.x e v1.4.0
* ❌ Renomear funções públicas — quebra API consumida em
  `studies/arc_flash_study.py`
* ❌ Adicionar parâmetros obrigatórios sem default — quebra callers
* ❌ Mover constantes existentes para módulo novo — quebra imports
* ❌ Escrever fórmula com base em "memória" ou "lembrança" —
  cita fonte sempre
