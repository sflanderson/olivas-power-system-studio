**Anti-alucinação registrada (3 bugs detectados)**:

**Bug A.2.1**: `test_small_xfmr_pickup_200pct_is_FAIL` — pickup 200% caiu no boundary do range WARN (167-200%), resultando WARN não FAIL. **Fix**: usei pickup=12.5A (250% FLA, claramente fora do WARN range) — teste corrigido, regra preservada.

**Bug A.2.2**: `test_slow_protection_above_damage_is_FAIL` (XFMR) — meu mental model de IEC SI a M=18.75 era ~91s mas o cálculo correto é ~4.6s. Como damage=5.5s, `4.6 < 5.5` → PASS (correto fisicamente). **Fix**: encontrei cenário FAIL real (TMS=10, M=31.25, I_pu=25 onde damage=2s mech floor) — t_prot=19.6s >> 2s → FAIL óbvio. Validado com cálculo manual via operating_time_s.

**Bug A.2.3**: `test_slow_protection_FAIL` (motor thermal) — relé com 51 ativo (TMS=0.30, pickup=120) vencia o composite a 600A com t=1.28s, então a regra dava PASS (correto pois proteção ESTÁ abaixo do damage 10s). **Fix**: usei `TCCDevice` direto sem 51, apenas com `TCCSegmentDefiniteTime` 49 — isolando a regra para testar o cenário real "só 49 ativo, lento".

Os 3 bugs reforçam: **a disciplina TDD com cálculo manual + cenários de fronteira detecta erros de mental model imediatamente, sem alucinação**.

**Princípios respeitados**:
- ✅ Cada Rule cita norma + página + valor literal
- ✅ Helper functions (_find_segment_with_id_substring, _get_pickup, _na, _target_id) para reduzir boilerplate
- ✅ Cada rule tem teste PASS + WARN + FAIL + NOT_APPLICABLE
- ✅ Tests usam targets reais (MultiFunctionRelay/CableDamageCurve/etc.) — não dummies — para integração full-stack
