## 1. Handoff Spec — Pin Categorization

### Overview

Pinos agora são categorizados visualmente por **função elétrica**
(power/signal/trip), com cores distintas e labels visíveis quando
componente está selecionado. Endereça gap UX onde v2.0.1 dots eram
todos cinza idênticos.

### Topology esperada

```
[BUS] ── T1.BREAKER ── T2.BREAKER ── P1.CT ── P2.CT ── [MOTOR/LOAD]
                       │              │
                       Trip_in        S1 (secundário)
                       │              │
                       │              ↓
                       └── Trip_out.RELAY ←── TC_link.RELAY
```

### Design Tokens — Pin Colors

| Token | Hex | Categoria | Aplicação |
|-------|-----|-----------|-----------|
| `pin-power` | `#1976D2` | POWER | Corrente nominal/falta (T1/T2 BREAKER, P1/P2 CT, terminais MOTOR) |
| `pin-signal` | `#2E7D32` | SIGNAL | Medição (S1/S2 CT, TC_link RELAY, Aux pins) |
| `pin-trip` | `#E65100` | TRIP | Lógica proteção (Trip_in BREAKER, Trip_out RELAY) |
| `pin-unknown` | `#505050` | UNKNOWN | Default fallback |
| `pin-selected-ring` | `#0078D7` | SELECTED | Halo azul quando componente selecionado |
| `pin-fill` | `#FFFFFF` (alpha 230) | — | Centro do dot (highlight do furo) |

### Components

| Component | Variant | Pin Categories | Notas |
|-----------|---------|----------------|-------|
| `BREAKER` | default | T1/T2 = POWER, Trip_in = TRIP | Disjuntor controlado por relé |
| `CT` | default | P1/P2 = POWER, S1/S2 = SIGNAL | Transformador de corrente |
| `RELAY` | default | T1/T2 = POWER (aux), TC_link = SIGNAL, Trip_out = TRIP | Relé de proteção |
| `FUSE` | default | T1/T2 = POWER | + state property (closed/open) |
| `CONTACTOR` | default | T1/T2 = POWER | + state property |
| Outros 51 specs | default | heurística por nome+label | Inferido automaticamente |

### States and Interactions

| Element | State | Behavior |
|---------|-------|----------|
| Pin dot | Default (componente não-selecionado) | Cor da categoria, raio 2.5px, fill branco |
| Pin dot | Componente selecionado | Raio 3.5px (1.4×) + ring azul ao redor (raio +1.5) |
| Pin dot | Componente inativo | Mesmo dot, mas overlay cinza translúcido (v1.7.1) cobre região |
| Pin label | Componente NÃO-selecionado | Não visível (anti-clutter) |
| Pin label | Componente selecionado | Texto 7pt em azul, offset 6px na direção oposta ao centro |

### Edge Cases

| Caso | Comportamento |
|------|---------------|
| Spec sem labels | `pin_specs_aligned()` usa name canônico (P1, S1, etc) |
| Spec ausente do registry | Names genéricos `pin1`, `pin2`, ... + categoria UNKNOWN (cinza) |
| Renderer sem `pin_positions()` | `_paint_pin_dots` retorna early; sem dots desenhados |
| Componente type não-padrão | Heurística aplica nomes; UNKNOWN se nenhum match |
| Hover não implementado | (escopo travado — só select faz mudança visual) |

## 2. Topology Validator

### API

```python
from app.preprocessor.topology_validator import (
    validate_protection_chain,
)

result = validate_protection_chain(
    components=[...],   # com 'id' e 'type'
    wires=[...],        # com 'from', 'to', 'from_pin', 'to_pin'
)

# result.valid: bool
# result.warnings: list[str]
# result.errors: list[str]
# result.components_found: dict[type → list[id]]
```

### Validações executadas

1. **Trip wire**: se há BREAKER + RELAY, verifica wire com
   `from_pin=Trip_out` ou `to_pin=Trip_in`
2. **CT secondary**: se há CT + RELAY, verifica wire com
   `from_pin=S1/S2` ou `to_pin=TC_link`

Validador **REPORTA** desvios; **NÃO BLOQUEIA** edição (anti-
acidental — usuário pode ter razões legítimas).
