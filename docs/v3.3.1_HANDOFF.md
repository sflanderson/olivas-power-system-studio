## 3. 4 Sub-sprints — todos GREEN

### Sub-sprint A — PowerFlowDialog N-bus (5/16 ✅)

**Audit gap §A.3**: PowerFlowDialog era hard-coded a 2-bus. N-bus exigia API programática.

**Fix em `app/gui/analysis_dialogs.py`**:
- NEW `build_pf_system_from_project(project, base_MVA=100.0)`:
  - Extrai BUS components do PpProject
  - First BUS → SLACK; demais → PQ
  - Conecta adjacent buses com branches (impedance default)
  - Aplica LOAD components (extract kW/kVAR de strings tipo "100 kW", "60 kvar")
- `run_power_flow_analysis` agora tenta N-bus first; cai em 2-bus dialog se project ausente
- Fluxo N-bus: skip dialog → solve direct → result_dialog ("Resultado PF (N-bus)")

**Reproduz**: PTW Tutorial §Part 2 p.63-76 (Run > Balanced System Studies).

### Sub-sprint B — EquipmentEvalDialog auto-load (1/16 ✅)

**Audit gap §C.3**: EquipmentEvalDialog carregava 7 demos, ignorava project real.

**Fix em `app/gui/main_window.py:_on_show_equipment_eval`**:
- Após instanciar `EquipmentEvalDialog`, tenta:
  - Detectar `self.schematic_pp.scene.project`
  - Chama `build_equipment_from_project(project)` (v3.3.0 Sprint 4)
  - Se há equipamentos extraídos → `dlg.set_equipments(extracted)`
- Falha silenciosa: dialog cai em demo data padrão se project ausente

**7ª garantia**: usuário Ctrl+E vê seus próprios equipamentos avaliados.

### Sub-sprint C — KT/KG/KSO em calculate_short_circuit (4/16 ✅)

**Audit gap §D.5**: KT/KG/KSO existiam (v3.3.0 Sprint 5) mas caller tinha que aplicar manualmente.

**Fix em `app/standards/iec60909.py:calculate_short_circuit`**:
- NOVO parâmetro `correction_factor: float = 1.0`
- Quando ≠ 1.0 → `z_thevenin_ohm *= correction_factor`
- Caller passa produto KT × KG × KSO para correção combinada
- Validação: correction_factor ≤ 0 raise ValueError

Exemplo:
```python
kt = transformer_correction_factor_KT(voltage_factor_c_max=1.10, x_T_pu=0.05)  # 1.0146
kg = generator_correction_factor_KG(voltage_factor_c_max=1.10, x_d_subtransient_pu=0.20)  # 0.995
result = calculate_short_circuit(
    rated_voltage_kV=13.8,
    z_thevenin_ohm=complex(0.05, 0.50),
    correction_factor=kt * kg,  # combined
)
```

### Sub-sprint D — decay μ·q em calculate_short_circuit (4/16 ✅)

**Audit gap §D.5**: decay μ·q existia em `iec60909_decay.py` (v3.0.x) mas `calculate_short_circuit` hard-coded `Ib = Ik = Ik''`.

**Fix em `app/standards/iec60909.py:calculate_short_circuit`**:
- NOVOS parâmetros:
  - `breaker_min_delay_s: float | None = None` (típico 0.05 s)
  - `generator_x_d_subtransient_pu: float | None = None` (Xd")
  - `is_synchronous_motor: bool = False`
- Quando `fault_distance == NEAR_TO_GENERATOR` + Xd" + t_min fornecidos:
  - Chama `mu_factor(Ik''/IrG_ratio, t_min_s)` para μ
  - `Ib = μ × Ik''` (per IEC 60909-0:2016 §4.5)
  - Síncrono: Ik = Ib; Async motor: Ik = 0.5 × Ib (q simplificado)
- Fallback: se algum param ausente → mantém comportamento legado (Ib = Ik''')

**Validação golden**:
- For Xd''=0.20, t_min=0.05s, ratio=5.0 → μ ≈ 0.824 (conforme Fig 5 IEC)
- `Ib / Ik'' ≈ 0.82` confirmado em test

## 7. Anti-alucinação — limitações declaradas

1. **Sub-sprint A — branches default** — `build_pf_system_from_project` usa
   R=0.01, X=0.05 default para branches entre adjacent buses. Refinamento
   via Tr/CABLE properties deferred v3.3.2 (extração de impedance per-bus).

2. **Sub-sprint A — Slack assumption** — primeiro BUS é assumido SLACK.
   Para escolha explícita (PV bus de generator), v3.3.2 adicionará
   propriedade `bus_role` ao PpComponent BUS.

3. **Sub-sprint B — set_equipments faz mass-replace** — overwrites demo data.
   Hybrid mode (demo + project) não suportado.

4. **Sub-sprint C — produto KT × KG × KSO é caller responsibility** — Olivas
   não detecta automaticamente quais elementos próximos do fault precisam
   correção. Auto-detection deferred (precisa topology-aware impedance walker).

5. **Sub-sprint D — q factor approximação 0.5** — para async motors. Real q
   factor IEC §4.6 exige `n_per_unit_per_second` (motor speed gradient) que
   não é conhecido sem dados do motor caller. v3.3.2 pode aceitar como param.
