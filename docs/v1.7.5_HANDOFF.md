---

## 1. Contexto + root cause

v2.0.1 (Sprint C) implementou `populate_from_cache()` em cada
plot dock + chamada em `_ensure_plot_dock`. Isso resolveu o caso
"abrir dock vazio quando estudo já rodou" — agora dock abre
**populado**.

Mas restava um gap: se o dock **já está aberto** quando o usuário
roda F5 (Power Flow novo), o dock **não atualiza** — mantém dados
antigos ou empty state. v1.7.5 fecha esse gap.

## 2. Solução (cirúrgica)

### Sprint A — Auto-refresh helper + hook

**NEW** `app/gui/plot_dock_refresh.py` (~80 LOC):

```python
def refresh_open_plot_docks(main_window) -> int:
    """Atualiza todos os 4 plot docks abertos a partir do study cache.

    Returns count of refreshed docks.
    """
    cache = main_window._study_cache()
    refreshed = 0
    for attr in (_plot_dock_pf_voltage, _plot_dock_sc_pie,
                 _plot_dock_tcc_overlay, _plot_dock_mc_hist):
        dock = getattr(main_window, attr, None)
        if dock and hasattr(dock, "populate_from_cache"):
            try:
                dock.populate_from_cache(cache)
                refreshed += 1
            except Exception:
                pass  # anti-crash
    return refreshed
```

**Hook** em `_dispatch_analysis` (main_window.py):
- Após dispatch bem-sucedido, antes do `except`:
- Chama `refresh_open_plot_docks(self)`
- Log no console: "v1.7.5: N plot dock(s) atualizado(s)..."
- try/except defensivo — refresh nunca derruba fluxo principal
