## 2. Estratégia v1.7.1 (anti-perda + anti-acidental)

### 2.1 Decisão de design

**Adicionar `is_active: bool = True` ao PpComponent** ao invés de
modificar 56 arquivos YAML:

* ✅ Anti-perda: dataclass field com default — backward compat
  total. Código existente que constrói PpComponent sem
  `is_active` continua funcionando.
* ✅ Anti-acidental: 1 arquivo modificado vs 56 YAMLs editados.
* ✅ Cobertura: TODOS os 56 components ganham suporte
  automaticamente (cada PpComponent tem `is_active`).

### 2.2 Para switching components (BREAKER/FUSE/etc)

Adicionar property `state: enum [closed, open]` no YAML.
Apenas **8 components** vs 56:

* BREAKER.ocomp
* FUSE.ocomp
* CONTACTOR.ocomp
* VCB.ocomp (se existir)
* VCB3.ocomp (se existir)
* SWITCH.ocomp (se existir)

### 2.3 Renderer hook

Items.py: verificar `component.is_active` antes de renderizar; se
False, aplicar overlay cinza translúcido. Edit cirúrgico de ~5
linhas no método paint().
